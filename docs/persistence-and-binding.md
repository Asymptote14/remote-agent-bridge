# 会话记忆与设备身份绑定

## 会话历史

Gateway 将用户、设备、会话、最近消息和任务保存到 `.rab/state.json`。手机通过 `GET /api/dashboard` 读取自己的会话列表、当前会话的消息和任务快照；`GET /api/sessions/:id/messages` 仍可独立查询消息。响应不会被共享缓存。账号 Token 只放在当前标签页的 `sessionStorage`，页面退出不等于服务端撤销。

用户密码和登录会话 Token 只以带随机盐的 scrypt 哈希保存。旧版本中曾保存的明文会话 Token 会在 Gateway 首次启动时自动迁移为 `token_hash`；现有浏览器 Token 仍然有效，重新登录后会生成新的随机 Token。

发送新消息时，Gateway 给任务附上该会话最多 20 条上下文，并限制序列化大小；Agent Provider 决定如何使用这些内容。CLI 通过自己的外部会话恢复上下文，不能把 RAB 侧删除会话视为删除第三方会话。

当前消息保留上限是每个会话 100 条，后续可以改为数据库分页和可配置保留期。不要把 `.rab/state.json` 提交到 Git，它已经被 `.gitignore` 忽略。

## 任务记录与回执

1. Gateway 将任务状态及关联的用户消息写入同一份 JSON 快照后，才将指令发送给 Agent。写入失败则不发送；终态和对应的会话回复也一起写入，持久化后才发 `task.ack`。
2. Agent 将收到的派发、执行开始和最新结果写入 `agent-task-receipts.json`。受同一授权版本、派发 ID 和序号约束。手机重复提交同一内容与编号只查原记录，不触发执行，复用旧编号提交不同内容会冲突（旧数据没有请求摘要时保持只查原记录的行为）。
3. 新协议重连时 Gateway 仅发送尚未终结的引用和取消意图。Agent 可以回传已有结果；没有回执就显式标为未知，不补发执行指令。Agent 进程重启后，旧的排队回执变成未执行；正在运行的回执变为未知，并暂停接单，直至 [本机核对](operations.md#恢复暂停的队列)。
4. 任务与回执约保留 24 小时，队列和快照有容量限制；当旧记录已清理时不能依赖旧编号再次提交仍然幂等。强制关机时不承诺恰好执行一次或跨文件事务。

两份快照分别通过临时文件替换写入，不是多实例可共享的数据库。只运行一套 Gateway / Agent；使用同一数据目录。如果快照无法解析，保留原文件并参考 [升级与回退](operations.md#升级与回退)，不要清空再尝试恢复。

## 一次配对，长期绑定

1. Agent 首次运行生成 Ed25519 密钥对，私钥（PKCS8，0600）保存在 `.rab/agent-identity.json`，**从不外发**。
2. 连接时 Agent 先发 `agent.challenge`，Gateway 回一个一次性 nonce（每次连接都不同）；Agent 用私钥签名该 nonce，在 `agent.hello` 中带上公钥、签名，以及本机证明（`local_proof`，即 setup token，见下文）。
3. Gateway 完成握手：已绑定设备必须用配对时登记的公钥验签（旧版迁移例外）；未绑定设备必须提供本机证明。通过本机证明的未绑定连接仅可交换握手、心跳和绑定通知等控制帧，收不到配对码、会话或任务。
4. 配对码只显示在电脑本机的 `/setup` 页面（`GET /api/setup/status`），60 秒有效、一次性；手机登录后提交配对码完成授权。
5. 授权时 Gateway 把当前连接**已经证明持有**的公钥写进设备记录（`auth_public_key`）；不再下发任何长期秘密。
6. 以后 Agent 重启时重新签名新的 nonce 即可恢复绑定，不再要求配对码。私钥文件泄露才会危及设备身份，而它不像 token 那样在网络上传输过。

> 兼容旧版本：如果设备是在 Ed25519 之前用随机 bearer token 绑定的，Agent 会同时带上旧 token 和新的公钥签名；Gateway 验过 token 后把设备升级为公钥绑定并删除 token 哈希，此后旧 token 立即失效。

### 为什么需要本机证明（setup token）

回环地址**不是**本机证明。本项目支持的隧道客户端（樱花 / frp 一类的转发，以及多数反向代理）都是先从 `127.0.0.1` 连到 Gateway 再转发流量，所以**每一个穿过隧道的请求在 Gateway 眼里都来自本机**。如果只按来源 IP 判断，攻击者只要够到隧道地址就能：

- 自己签发配对码，把用户电脑绑定到攻击者账号；
- 抢先占住唯一的 Agent 槽位，让操作者随后在配置页签发的配对码发给**攻击者的连接**，从而让攻击者的公钥被绑定成这台电脑。

因此所有特权操作（`/api/setup/*`）除了要求回环来源，还必须带上存在 `.rab/setup-token` 的本机密钥（请求头 `x-rab-setup-token`）；只有能读到本机数据目录的进程才拿得到它。Agent 走同一条路径：它跑在本机，能读到该文件，因此在 `agent.hello` 里用 `local_proof` 证明；穿隧道过来的对端读不到，无法冒充。

配置页通过 `scripts/rab.ps1 open` 启动时会把 `?token=…` 带进 URL，页面取出后存入 `sessionStorage` 并尽快从地址栏清除。常规 Gateway 请求日志不记录 URL 查询；仍不要分享这样的链接，并非所有代理或应用日志都适用该保护。

安全属性：

- 握手未通过的连接受超时限制；它可以请求一次挑战，认证之前不会收到任务或会话。
- 每次连接使用新的 nonce：录下来的握手签名在下一个连接上无效；换一把私钥冒充同一 `DEVICE_ID` 会被拒绝（`device_identity_invalid`）。
- 槽位仲裁：已认证设备始终优先；本机 Agent 可以顶掉**未认证**的占用者（这样重启后的本地 Agent 不会被残留连接挡住）；已认证的占用者不会被其他设备 id 顶掉，防止连接抢占。
- 只有已认证、或已证明本机的连接才会被签发配对码（否则返回 `agent_not_trusted`）。
- 撤销设备会清除服务端登记的公钥（以及可能残留的旧 token 哈希）并断开连接，需要重新配对。未审批任务直接取消；已派发但无可靠停止证明的任务标记为未知。撤销后的重新配对不继承上一授权的待执行任务。
- 配对码只用于第一次绑定或用户主动重新绑定，不是日常登录凭证。
- 配对授权接口要求 6 位数字验证码，并按来源 IP 限制失败次数；连续失败后需要等待窗口结束。
- HTTP API 只接受当前 Gateway 地址、配置的 HTTPS 地址或本机地址作为浏览器 Origin；Agent WebSocket 也执行同样的来源检查。
- `state.json`、Provider 配置、Agent 身份文件和 setup token 尝试使用仅所有者可读写的文件权限；Windows 上仍应依靠用户账户 ACL 保护 `.rab` 目录。

### 数据目录

`.rab/` 统一锚定在**工作区根目录**（包含 `pnpm-workspace.yaml` 的那一层），不再按 `process.cwd()` 解析。否则 `pnpm dev` 会让 Gateway 和 Agent 各自在包目录下解析出不同的数据目录，从而拿到不同的 setup token、读写不同的身份文件。可以用 `RAB_DATA_DIR` 覆盖。

## 第三方 Agent

配置页支持添加 HTTP Provider，保存到 `.rab/providers.json`，重启后 Agent 会加载。CLI、MCP、WebSocket 和 GUI Agent 继续按照 `@rab/adapter-sdk` 实现对应 Adapter，不需要修改手机端协议。
