# Remote Agent Bridge · 私网试用手册

适用范围：一位操作者、一台 Windows 电脑、一个 Gateway/Agent 实例，共用一套数据目录。先在本机验证，再接入自己控制的私网。不要在本轮上线公网、共享账号或启用此前未验证的高权限 Provider。

## 首次验证

1. 安装 Node.js 22 或 24，在项目根目录运行 `pnpm install`、`pnpm setup`。默认启动器使用项目下的 `.rab/` 和本机 `127.0.0.1:8787`。`pnpm status` 可以查看启动器记录的进程；配置页能看到 Agent 是否连接。
2. 在电脑配置页选择「重新生成配对码」。在同一台电脑打开 `http://127.0.0.1:8787/`，注册或登录。点击「绑定电脑」，输入一次性配对码；不要把配对码或配置页启动链接发给别人。
3. 等待「电脑在线」，新建会话并保留默认「本机只读（Local）」。发送「现在几点」，确认看到一条结果。刷新，切换会话再回来，确认历史和任务状态都在且不重复。
4. 需要用手机时，先读 [可信私网访问](network-access.md)。用私网手机再做一次登录、配对（尚未绑定时）、任务、锁屏恢复和刷新；浏览器模拟视口不等于真机验收。若要给另一账号配对，先完成现有任务，再用当前账号在会话菜单选择「解除电脑绑定」，到本机重新签发配对码。

## 任务状态与操作

| 界面状态 | 准确含义 | 应该怎么做 |
|---|---|---|
| 等待你确认 | 任务已写入 Gateway，尚未发给电脑 | 检查完整输入；不确定就拒绝，5 分钟未批准自动过期 |
| 等待电脑接单 | Gateway 已保存，尚未收到 Agent 的接单回执 | 等待状态更新；丢 HTTP 回执也不要生成新编号重发 |
| 电脑已接单 · 排队中 | Agent 已保存回执，任务尚未开始准备或执行 | 可请求取消；排队超过 30 分钟的任务不会开始 |
| 电脑正在执行 | 正在准备会话或执行 Provider | 可请求取消，结果以最终状态为准 |
| 已请求取消 · 等待确认 | Gateway 已记录取消意图，不代表执行已经停止 | 若电脑离线，等其重连；不要在此状态签发同一任务 |
| 已取消 | 确认前拒绝、开始前已移除，或者执行已确认停止 | 阅读卡片说明，取消不会撤销已发生的副作用 |
| 结果未知 | 缺少可靠的最终回执，或无法确认 Provider 已停止 | 在电脑或 Provider 核对结果、文件和进程；不要把未知当作未执行 |

Gateway 断线重连只同步任务引用和回执，不重发任务输入。同进程仍持有且重新验证授权的排队项可以继续；Agent 重启后不会恢复旧队列的执行。留有「运行中」回执但没有终态时，新 Agent 保守暂停队列。最近任务约 24 小时留存，历史聊天另按每会话最近 100 条保存。旧版 Agent 没有持久回执或远程取消功能。

## 升级与回退

1. 停止提交新任务，让正在执行的任务结束或在电脑上核对已停止；不要用强制重启代替取消。用 `pnpm stop` 停止启动器管理的服务；如从 `pnpm dev` 或其他终端启动，请在相应终端停止，另外检查 Provider 是否仍在运行。
2. 在服务停止后，做一份只供本机操作者访问的完整数据目录备份。应一起备份 `state.json`、`agent-task-receipts.json`（升级后生成）、`agent-identity.json`、`setup-token`、配置和 Provider 会话映射。自定义路径的配置文件也要单独备份。这里有私钥、Token 与聊天内容，不要上传、共享或提交到 Git。
3. **同时更新与编译 Gateway 和 Agent**，保留同一个数据目录。新 Gateway 能识别无回执能力的旧 Agent，但不提供同等取消与恢复；不支持新 Agent 搭配旧 Gateway 接单。配置如果还指向 `.cmd` / `.bat`，先换成直接可执行文件或实际 Node 入口。
4. 用 `pnpm start` 启动；确认配对仍有效，用 Local 发一条只读任务。回退时先再次停机，保留升级后的目录副本，然后用**旧代码与对应升级前备份**一起恢复到隔离位置。恢复旧备份不会包含升级后新增记录；先核对实际执行，再决定后续处理。不要叠加新旧进程或回放旧输入。

Windows 启动器仍以默认端口与目录为基线。用自定义 `GATEWAY_PORT`/`RAB_DATA_DIR` 的实例测试前，确认实际监听地址、配置文件与两端进程使用的是同一套数据；不能仅凭启动器状态判断。停机脚本只处理它记录的进程，不保证第三方 Provider 的所有进程退出。

## 恢复暂停的队列

仅在手机显示队列暂停，且本机操作者已完成以下检查时使用：

1. 停止 Gateway 和 Agent，确认没有另一个 Agent 实例使用同一数据目录。检查有关的任务结果和 Provider 进程（远端 HTTP Provider 在对端检查），确认旧任务不会继续运行。仍不确定就保持暂停。
2. 备份数据目录。进入项目根目录，使用当前已编译版本、同一个数据目录运行：

   ```powershell
   node services/agent/dist/index.js --acknowledge-stopped --confirm-local-cleanup
   ```

3. 上述命令**只记录本机确认并解除暂停**，不查杀进程、不改写旧任务结论、不重新运行旧任务。确认显示 `Cleanup acknowledged` 后再启动服务，先用 Local 验证。

若启动时报 `state_unreadable` 或 `receipt_journal_unreadable`，先保留现场文件，恢复一致备份或检查损坏；不要为了恢复接单直接删除日志、回执或设备身份。遇到 `state_write_failed`，检查磁盘空间、目录权限和文件占用，恢复后用原任务编号查询。

## 复现测试

```powershell
npm test
node apps/gateway/tests/live-smoke.mjs
node apps/web/tests/browser-smoke.mjs
```

两条冒烟脚本需要先构建（`npm test` 已构建，或者单独跑 `npm run typecheck:tsc`）。脚本启动独立的本机端口和临时数据目录；真实 Agent 冒烟使用 Local，不请求第三方模型。浏览器脚本单独运行，不算在 `npm test` 的数量里：在能导入 `playwright` 且装有 Chromium 的环境执行，或用绝对路径变量 `RAB_PLAYWRIGHT_MODULE` 指向 Playwright 的 `index.mjs`，用 `RAB_CHROMIUM_EXECUTABLE` 指向已安装 Chromium/Edge。浏览器流程用测试账号、真实 Gateway 和受控 Agent 夹具，故障模拟不会连接真实 Provider。
