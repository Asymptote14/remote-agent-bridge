# 可信私网访问

手机浏览器访问 Gateway；同一台电脑上的 Agent 单独通过 `/agent` WebSocket 连接 Gateway。浏览器使用同源 HTTP API，不需要连接 `/agent`，也不需要把 WebSocket Upgrade 暴露给手机。当前 `/agent` 与 Web 共用监听端口，仅靠设置手机 URL 不能分隔这两个入口。

## 推荐顺序

1. 先用默认监听 `127.0.0.1:8787` 完成 [本机验证](operations.md#首次验证)。本机能通过不代表手机路径或 TLS 已验收。
2. 让电脑与手机加入只有你能控制的虚拟局域网。保护该网络的成员和接入规则，不要做公网端口映射或使用匿名可访问的入口。
3. 保留 Gateway 回环监听、通过已有的**私网专用 HTTPS 反代**暴露手机工作台是优先选择。反代应转发 `/`、`/assets/` 与普通用户 API，不转发 `/agent`、`/setup`、`/api/setup/`。验证浏览器实际收到可信 HTTPS 证书；在配置页填写 `https://` 地址只是在设置链接和来源地址，不会自动启用 TLS、访问控制或证书。
4. 如果在测试中使用虚拟网卡私有地址直连，设置页的「虚拟局域网」模式默认监听 `0.0.0.0`（包括 Agent 使用的回环入口），不会自动限制来源。只在防火墙、虚拟网及来源范围均已验证时使用；在明文 HTTP 中，密码、Token 和消息不受应用层传输加密。不要直接改成仅监听虚拟网卡地址而切断本机 Agent 的回环连接。
5. 在手机浏览器打开私网地址，确认未登录不能读历史，登录后只看得到当前账号的会话，再执行一条只读 Local 查询。测试刷新、切换网络、锁屏和恢复。

```text
手机浏览器 ── 私网 HTTPS ── 受控反代 ── Gateway（127.0.0.1:8787）
                                            ↑
                                       本机 Agent（/agent）
```

## 管理入口和旧隧道配置

- 电脑本机用 `pnpm setup` 打开管理页；不要把含 setup token 的配置链接发到手机或其他设备。回环来源可能来自反代转发，故管理 API 必须同时验证本机 token；反代仍应主动屏蔽管理和 Agent 路径。
- 保留了 `sakura`（樱花）旧配置的 HTTPS URL 校验，用于兼容既有配置；**不推荐将樱花公网地址或其他公开隧道作为此版本的部署方式**。HTTPS URL 校验不是公网发布验收。
- 如果必须使用自定义端口或数据目录，当前 Windows 启动器的启动/状态/打开配置页尚未统一这些参数。用独立数据目录先按 [运维手册](operations.md#升级与回退) 演练。
- Provider 定义默认位于 `.rab/providers.json`。只有本机管理面可以改变 Provider 配置，环境变量 `RAB_PROVIDERS_FILE` 优先于配置文件路径。

当前仍未实现面向公开访问的账号会话到期/注销、MFA、完整审计与独立管理监听器。不要把 Gateway 端口直接暴露到公网。
