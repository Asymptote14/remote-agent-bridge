# 非干扰执行设计

Remote Agent Bridge 的默认目标不是接管用户当前桌面，而是让 Agent 在电脑后台工作，同时用户可以正常玩游戏、看视频或使用办公软件。

## 默认隔离模式

所有任务默认带 `mode: isolated`，执行层遵守以下规则：

- Agent 是独立守护进程，不依赖手机页面、当前前台窗口或用户的鼠标键盘。
- 任务进入单独队列，默认一次执行一个任务，避免多个任务互相抢资源。
- 浏览器任务使用 Agent 专属浏览器进程和独立用户目录，不复用用户正在使用的 Chrome/Edge 窗口。
- Shell、文件和进程任务使用后台子进程，不调用全局鼠标/键盘注入。
- 截图使用窗口/桌面捕获接口，不通过移动鼠标或切换前台窗口完成。
- 每个任务有超时、取消句柄和输出大小上限。
- 每个任务有两个独立的时钟：**总时长预算**（默认 15 分钟，可用任务的 `timeout_ms` 或 `RAB_TASK_TIMEOUT_MS` 调整，上限 2 小时）和**静默预算**（默认 10 分钟完全没有输出即判定为挂起，可用 `idle_timeout_ms` 或 `RAB_IDLE_TIMEOUT_MS` 调整）。分成两个时钟是为了不把“慢”当成“卡死”：无头编码 Agent 跑真实仓库任务常常要几分钟，而一个卡在等待输入的进程会一直占住唯一的任务槽，所以只放宽总时长是不够的。
- 超时和取消都必须终止**整棵进程树**，而不只是直接子进程。Windows 上的 CLI 是通过 `cmd.exe /c <script>.cmd` 启动的，杀掉 `cmd.exe` 不会带走它启动的 node 进程——真正的 Agent 会继续跑、继续写文件、继续消耗额度。实现见 `services/agent/src/process-control.ts`。

## 前台模式

某些 GUI 软件只能在交互式桌面中操作。这类能力不能偷偷抢占用户桌面，必须：

1. 任务显式声明 `mode: foreground`。
2. 手机端展示“会影响当前桌面”的确认提示。
3. 用户确认后才允许执行。
4. 执行期间显示占用状态，并支持远程取消。

当前骨架会拒绝前台模式任务，保护用户正在使用的桌面。真正启用前台模式前，应优先实现 Windows 独立桌面/独立用户会话适配；无法隔离时宁可拒绝，也不要模拟全局鼠标键盘。

## Windows 部署建议

- Agent 以 Windows Service 或计划任务常驻运行，默认不创建窗口。
- Agent 服务进程与用户正在玩的游戏/应用进程分离。
- GUI 自动化使用专属工作目录和专属浏览器 Profile。
- 需要独立桌面的应用放到专门的 Windows 用户会话或虚拟桌面中。
- Agent 的 CPU、内存和并发都设置上限，避免后台任务影响游戏帧率。
- 提供本地紧急停止命令：`rab-agent stop`。

## 当前版本边界

已实现的执行器只有：`local`（只读系统查询——时间、系统信息、进程列表、工作目录内文件列表与读取）、`http`，以及 WorkBuddy 和 Codex 两个无头 CLI 适配器。**浏览器、Shell、截图和 GUI 执行器都尚未实现**，所以手机端目前发不出这几类任务。协议里的 `kind` 字段（`browser`/`file`/`process`/`screenshot`/`shell`/`gui`）、队列和模式字段已经按非干扰设计预留；将来接入这些执行器时必须继续遵守本文件，不能因为某个执行器实现方便，就直接复用用户的前台窗口。
